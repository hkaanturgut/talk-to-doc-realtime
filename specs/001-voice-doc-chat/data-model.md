# Data Model: Voice Chat with a Document or YouTube Video

All state is in memory. Server entities live in `DocumentStore`; client entities live in React state
via the `useVoiceSession` reducer. Types are defined once as zod schemas in `src/shared/schemas.ts`.

## SourceDocument (server)

| Field | Type | Rules |
|---|---|---|
| `id` | string | `crypto.randomUUID()`; unguessable, the only handle the client gets |
| `kind` | `"pdf" \| "youtube" \| "text"` | required |
| `title` | string | 1 to 200 chars; PDF file name without extension, video title, or "Pasted transcript" |
| `fullText` | string | normalized extracted text, before truncation |
| `contextText` | string | text actually sent to the model (prefix of `fullText`, cut at a boundary) |
| `charCount` | number | `fullText.length` |
| `estimatedTokens` | number | `ceil(charCount / 4)` |
| `truncated` | boolean | `contextText.length < fullText.length` |
| `usedRatio` | number | 0 to 1, `contextText.length / fullText.length` |
| `pageCount` | number? | PDF only, ≥ 1 |
| `pagesUsed` | number? | PDF only, last page fully or partly included |
| `videoId` | string? | YouTube only, `^[A-Za-z0-9_-]{11}$` |
| `durationSeconds` | number? | YouTube only, from the last caption segment |
| `captionLanguage` | string? | YouTube only, BCP-47 (e.g. `en`, `tr`) |
| `captionSource` | `"direct" \| "supadata"`? | YouTube only |
| `autoGenerated` | boolean? | YouTube only |
| `createdAt` / `lastUsedAt` | number (epoch ms) | `lastUsedAt` refreshed on every read |

**Limits**:
- PDF upload ≤ 25 MB (26,214,400 bytes; MB = 1,048,576 bytes everywhere).
- Pasted text ≤ 400,000 chars.
- `contextText` ≤ document budget (Azure 80,000 chars ≈ 20k tokens; OpenAI 360,000 chars ≈ 90k
  tokens).

**Lifecycle**:
1. `created` (ingest succeeded).
2. `active` (read by `/api/session`, which refreshes `lastUsedAt`).
3. `expired`: removed 60 minutes after `lastUsedAt`, or evicted earlier by LRU when the store holds
   more than 200 documents or more than 300 MB of text.
4. A missing id returns `DOCUMENT_NOT_FOUND`, and the UI asks the user to load the document again.

**PreviewDTO** (returned to the client): every field except `fullText`. It includes `contextText` for
the preview and `fullTextTail`, the first 500 chars after the cut point, so the preview can show where
truncation happened.

## ConversationSession (client)

| Field | Type | Rules |
|---|---|---|
| `mode` | `"voice" \| "text"` | voice by default; text if mic unavailable/denied or chosen |
| `status` | see state machine | |
| `muted` | boolean | voice only |
| `startedAt` | number? | set when status first becomes `live` |
| `capEndsAt` | number? | `startedAt + sessionMaxSeconds` (900 s from `/api/session`); warning at `capEndsAt - 2 min`; **not reset by reconnects** |
| `reconnectAttempt` | number | 0 and up; delays 1, 2, 4, 8, 8, 8... s until `reconnectDeadline` |
| `reconnectDeadline` | number? | first drop + 30 s |
| `error` | `{ code: ErrorCode, message: string }?` | last fatal error |

**State machine** (`status`):

```text
idle ──start──▶ requesting_mic ──granted──▶ connecting ──dc open──▶ live
  ▲                 │ denied/no device                    │
  │                 └──────────▶ idle(mode=text) ◀─────────┤ user switches to text
  │                                                        │
  │   live ⇄ (listening | thinking | assistant_speaking)  sub-state from audio buffer + VAD events
  │                                                        │
  │                 live ──offline / data channel close / pc disconnected 2s / failed──▶ reconnecting ──ok──▶ live
  │                                                        │ 30 s elapsed
  │                                                        ▼
  └──────────────stop / cap reached──────────────── disconnected ──Reconnect──▶ connecting
                                                     error (fatal, non-retryable) ──retry──▶ connecting
```

Rules:
- `start` is ignored unless the status is `idle`, `disconnected`, or `error` (prevents double taps).
- `stop` from any state releases the mic tracks, closes the data channel and peer connection, and sets
  the status to `idle`.
- `muted` toggles `track.enabled`. It never renegotiates.

## TranscriptEntry (client)

| Field | Type | Rules |
|---|---|---|
| `id` | string | realtime `item_id` (user) or `response_id:item_id` (assistant) |
| `speaker` | `"user" \| "assistant" \| "system"` | `system` for notices (e.g. "Reconnected") |
| `text` | string | accumulated from deltas |
| `status` | `"in_progress" \| "final" \| "interrupted"` | |
| `order` | number | position in the conversation, assigned from `conversation.item.added` (`previous_item_id`), so late user transcripts land before the assistant reply that followed them |
| `at` | number | epoch ms of first delta |

**History for reconnect**: the most recent finalized `user` and `assistant` entries, at most 40 items
and 8,000 chars total (oldest dropped first), sent in chronological order (oldest first) as
`history: [{speaker, text}]` in the `/api/session` request.
